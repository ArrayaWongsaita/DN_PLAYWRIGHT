# บทที่ 31: ควบคุมเวลาด้วย page.clock

บทนี้เขียนให้อ่านเองได้ ตัวอย่างทุกอันรันได้จริง ลองรันแล้วแก้ค่าเล่นดูระหว่างอ่าน

## จบบทนี้แล้วทำอะไรได้

- อธิบายได้ว่าทำไม test ที่ตรวจข้อความที่ขึ้นกับเวลาต้อง "กำหนดเวลา" เอง
- ตั้งเวลาให้หน้าเว็บด้วย `page.clock.install` และหยุดเวลาด้วย `pauseAt`
- เดินเวลาไปข้างหน้าด้วย `runFor` และกระโดดข้ามเวลาด้วย `fastForward`
- ตั้งเวลาคงที่ด้วย `setFixedTime` เพื่อทดสอบคำทักทายตามช่วงเวลา

## เชื่อมกับที่รู้แล้ว

ในบทก่อนหน้านี้เราเลี่ยงการตรวจข้อความที่ขึ้นกับเวลา (คำทักทาย วันที่ ตัวนับ Flash Sale) เพราะผลเปลี่ยนตามเวลาที่รัน test ใน Jest คุณอาจเคยใช้ `jest.useFakeTimers()` และ `jest.setSystemTime()` ซึ่งเป็นแนวคิดเดียวกัน `page.clock` คือ fake timers ของ Playwright แต่ทำงานใน browser จริงที่หน้าเว็บของเราใช้อยู่

## เนื้อหา

### 1. ทำไมต้องกำหนดเวลา

หน้าแรกของแอป (`/`) มีสามอย่างที่ขึ้นกับเวลา:

| สิ่งที่แสดง | กฎ |
|---|---|
| คำทักทาย `data-testid="greeting"` | 05:00-11:59 "สวัสดีตอนเช้า", 12:00-16:59 "สวัสดีตอนบ่าย", เวลาอื่น "สวัสดีตอนเย็น" (ตามเวลาเครื่องผู้ใช้) |
| วันที่ `data-testid="today"` | วันที่เต็มตามภาษาของ browser |
| Flash Sale (`role="timer"` ชื่อ "เวลาที่เหลือ") | "เหลือเวลา HH:MM:SS" นับถอยหลังถึง 2030-12-31 23:59:59 (+07:00) อัปเดตทุก 1 วินาที ถ้าเหลือตั้งแต่ 1 วันขึ้นไปเป็น "เหลือเวลา N วัน HH:MM:SS" พอหมดเวลาเป็น "Flash Sale จบแล้ว" |

ถ้าเขียน test โดยไม่ควบคุมเวลา ผลขึ้นกับว่ารันตอนไหน: รันตอนเช้าผ่าน รันตอนเย็นพัง ตัวนับเปลี่ยนทุกวินาที ข้อความที่ตรวจจึงไม่เคยตรงตัวสองครั้ง และรันบนเครื่อง CI ที่อยู่คนละ timezone ก็ได้ผลต่างกัน ทางแก้คือบอก browser ว่า "ตอนนี้กี่โมง" เอง

**timezone**: `playwright.config.ts` ตั้ง `timezoneId: "Asia/Bangkok"` และ `locale: "th-TH"` ไว้แล้วผ่าน `sharedUse` ทุก test จึงเห็นเวลาเป็นเวลาไทยไม่ว่าเครื่องอยู่ที่ไหน และเราเขียนเวลาในโค้ดแบบมี `+07:00` กำกับเสมอ (`new Date("2030-12-31T23:00:00+07:00")`) เพื่อให้ชี้ช่วงเวลาเดียวกันทุกเครื่อง

### 2. page.clock.install: ติดตั้งนาฬิกาปลอม

```ts
await page.clock.install({ time: new Date("2030-12-31T22:00:00+07:00") });
await page.goto("/");
```

`install` แทนที่ `Date`, `setTimeout`, `setInterval`, `requestAnimationFrame` ฯลฯ ของหน้าเว็บด้วยของปลอมที่ Playwright คุมได้ **ต้องเรียกก่อน `page.goto`** เพราะ Playwright ฝังนาฬิกาปลอมเข้าไปก่อนสคริปต์ของหน้าทำงาน ถ้าเรียกหลังโหลดหน้า โค้ดของหน้าที่ตั้ง `setInterval` ไปแล้วจะยังใช้ตัวจริงอยู่ ตัวนับจึงไม่ตามนาฬิกาปลอม

หลัง `install` เวลาที่ตั้งจะ "เดินต่อตามปกติ" ตามเวลาจริงจนกว่าเราจะหยุดมัน (ยังไม่นิ่ง ยังตรวจแบบแม่นยำไม่ได้) ขั้นต่อไปคือหยุดเวลา

### 3. pauseAt: กระโดดไปเวลาที่ต้องการแล้วหยุด

```ts
await page.clock.install({ time: new Date("2030-12-31T22:00:00+07:00") }); // เริ่มก่อนเวลาที่ต้องการ
await page.goto("/");
await page.clock.pauseAt(new Date("2030-12-31T23:00:00+07:00")); // กระโดดไป 23:00:00 แล้วหยุด

await expect(page.getByRole("timer", { name: "เวลาที่เหลือ" })).toHaveText("เหลือเวลา 00:59:59");
```

- เอกสารแนะนำให้ติดตั้งนาฬิกาที่เวลา "ก่อนเวลาเป้าหมายเล็กน้อย" แล้วให้หน้าโหลดตามปกติ จากนั้นค่อย `pauseAt` เวลาเป้าหมาย ช่วยให้ timer ต่างๆ ตอนโหลดหน้าทำงานปกติ ไม่ค้าง
- `pauseAt` ต้องเป็นเวลา "หลัง" เวลาปัจจุบันของนาฬิกาเสมอ (กระโดดถอยหลังไม่ได้)
- หลัง `pauseAt` จะไม่มี timer ทำงานจนกว่าจะสั่ง `runFor`, `fastForward` หรือ `resume()` ค่าบนหน้าจึงนิ่ง ตรวจได้แม่น ไม่สุ่ม
- ตัวเลข: หมดเวลา 23:59:59 ลบ 23:00:00 = 59 นาที 59 วินาที จึงเห็น "เหลือเวลา 00:59:59"

`expect` ยังรอเองตามปกติ (การรอของ Playwright ใช้เวลาจริง ไม่ใช่นาฬิกาปลอมของหน้า)

### 4. runFor: เดินเวลาไปทีละนิด

```ts
await page.clock.runFor("00:10"); // เดินไป 10 วินาที
await expect(timer).toHaveText("เหลือเวลา 00:59:49");
```

`runFor(ticks)` เดินนาฬิกาไปข้างหน้าและ **รัน timer ทุกตัวที่ถึงกำหนดระหว่างทาง** เหมือนเวลาผ่านไปจริง เช่น `setInterval` ทุก 1 วินาทีจะถูกเรียก 10 ครั้งใน 10 วินาที ใช้เมื่อต้องการให้พฤติกรรมที่ขึ้นกับเวลาเกิดขึ้นครบทุกขั้น

`ticks` เป็นมิลลิวินาที (ตัวเลข) หรือสตริง: `"08"` = 8 วินาที, `"01:00"` = 1 นาที, `"02:34:10"` = 2 ชั่วโมง 34 นาที 10 วินาที

### 5. fastForward: กระโดดข้ามเวลา

```ts
await page.clock.install({ time: new Date("2030-12-31T23:59:50+07:00") });
await page.goto("/");
await page.clock.fastForward("00:20");
await expect(timer).toHaveText("Flash Sale จบแล้ว");
```

`fastForward(ticks)` กระโดดไปข้างหน้าทีเดียว เปรียบเหมือนปิดฝาแล็ปท็อปแล้วเปิดใหม่หลังจากนั้น และ **รัน timer ที่ถึงกำหนดแล้วอย่างมากหนึ่งครั้ง** (ไม่ได้รันทุกรอบเหมือน `runFor`) ใช้เมื่อสนใจแค่ "ผลหลังจากเวลาผ่านไปนานๆ" เช่น ข้ามไปหลังหมดเวลา ใช้เวลาจริงน้อยกว่า `runFor` มากเมื่อข้ามเวลาเป็นชั่วโมง

| คำสั่ง | ทำอะไร | timer ที่ถึงกำหนด |
|---|---|---|
| `install({ time })` | ติดตั้งนาฬิกาปลอมเริ่มที่เวลานั้น (เวลาเดินเองต่อ) | ทำงานตามปกติ |
| `pauseAt(time)` | กระโดดไปเวลานั้นแล้วหยุดเวลา | รันอย่างมาก 1 ครั้งตอนกระโดด แล้วหยุดนิ่ง |
| `runFor(ticks)` | เดินไปข้างหน้า | รันทุกรอบที่ถึงกำหนดระหว่างทาง |
| `fastForward(ticks)` | กระโดดไปข้างหน้า | รันอย่างมาก 1 ครั้ง |
| `setFixedTime(time)` | ทำให้ `Date` คืนค่านี้ตลอด | timer ทำงานต่อตามปกติ แต่เวลาไม่ขยับ |
| `resume()` | ให้เวลาเดินต่อหลัง `pauseAt` | ทำงานตามปกติ |

### 6. setFixedTime: เวลาคงที่แบบง่าย

```ts
await page.clock.setFixedTime(new Date("2026-11-12T13:00:00+07:00"));
await page.goto("/");
await expect(page.getByTestId("greeting")).toHaveText("สวัสดีตอนบ่าย");
```

`setFixedTime` ทำให้ `new Date()` และ `Date.now()` คืนค่าเวลานั้นเสมอ **แต่ไม่ได้แทนที่ timer** (`setTimeout`/`setInterval` ยังเป็นของจริง) เหมาะกับหน้าที่ "อ่านเวลาครั้งเดียว" เช่น คำทักทายและวันที่ ข้อควรระวัง: ถ้าใช้กับตัวนับถอยหลัง Flash Sale ตัวนับจะนิ่งที่ค่าเดียวเพราะ `Date.now()` ไม่ขยับ (ถึง interval จะยังทำงาน) ถ้าต้องการให้ตัวนับเดินให้ใช้ `install` กับ `pauseAt`/`runFor`

คำทักทายคำนวณจาก `new Date().getHours()` ตอนหน้า mount ด้วย timezone ของ browser (Asia/Bangkok) จึงต้องตั้งเวลาก่อน `goto` ทดสอบรอยต่อของช่วงเวลาได้ด้วย `setFixedTime` เช่น 04:59 เป็น "เย็น" 05:00 เป็น "เช้า" (ข้อ 5)

วันที่ `today` จัดรูปแบบตามภาษา `th-TH` เป็นปีพุทธศักราช เช่น "วันพฤหัสบดีที่ 12 พฤศจิกายน พ.ศ. 2569" ตรวจเฉพาะส่วนที่เราสนใจด้วย `toContainText("12 พฤศจิกายน")` จะอ่านง่ายกว่าตรวจทั้งประโยค

## จุดที่มักพลาด

- **เรียก `install`/`setFixedTime` หลัง `goto`**: หน้าอ่านเวลาไปแล้ว ผลไม่เปลี่ยน ให้เรียกก่อน `goto`
- **`pauseAt` เวลาที่อยู่ก่อนเวลาปัจจุบันของนาฬิกา**: ใช้ไม่ได้ ให้ `install` ที่เวลาก่อนเป้าหมาย
- **ตรวจตัวนับหลัง `install` โดยไม่ `pauseAt`**: เวลายังเดิน ค่าที่ตรวจอาจเปลี่ยนเป็น "00:59:58" ก่อนตรวจ ให้หยุดเวลาก่อนตรวจค่าตรงตัว
- **เขียนเวลาไม่มี `+07:00`**: `new Date("2030-12-31T23:00:00")` ถูกตีความตาม timezone ของเครื่องที่รัน test ผลจึงต่างกันระหว่างเครื่อง
- **คาดว่า `fastForward` รัน interval ทุกรอบ**: รันอย่างมากครั้งเดียว ถ้าต้องการทุกรอบใช้ `runFor`
- **ใช้ `setFixedTime` แล้วรอให้ตัวนับเดิน**: เวลาไม่ขยับ ใช้ `install` แทน
- **ใช้ `waitForTimeout` รอเวลาเดิน**: ไม่ต้อง ใช้ `runFor` เดินเวลาให้ทันที

## หน้าในแอปที่ใช้

**`/`** หน้าแรก มี `greeting`, `today` และหัวข้อ "Flash Sale" ที่มี `role="timer"` ชื่อ "เวลาที่เหลือ" (หมดเวลา 2030-12-31 23:59:59 +07:00)

## แบบฝึกหัดในบทนี้

1. ตรวจ Flash Sale เมื่อเวลาเป็นเที่ยงวัน (`install` + `pauseAt`)
2. ให้เวลาเดินไป 10 วินาทีด้วย `runFor` แล้วตรวจว่าตัวนับลดลง
3. ข้ามเวลาจน Flash Sale จบด้วย `fastForward`
4. ตรวจคำทักทายและวันที่ของเช้าวันที่ 12 พฤศจิกายน (`setFixedTime`)
5. ตรวจคำทักทายตรงรอยต่อของช่วงเวลาทั้ง 6 จุด
