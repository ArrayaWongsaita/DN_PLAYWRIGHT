# บทที่ 17: ทำงานกับรายการ (หลาย element)

บทนี้เขียนให้อ่านเองได้ ตัวอย่างทุกอันรันได้จริง ลองรันแล้วแก้ค่าเล่นดูระหว่างอ่าน

## จบบทนี้แล้วทำอะไรได้

- นับ element ด้วย `toHaveCount`
- ตรวจข้อความทั้งรายการพร้อมลำดับด้วย `toHaveText([...])`
- เลือกเฉพาะใบที่ต้องการด้วย `first()`, `last()`, `nth()`
- วนทีละ element ด้วย `locator.all()` และรู้ว่าเมื่อไหร่ควรใช้ (และเมื่อไหร่ไม่ควร)

## เชื่อมกับที่รู้แล้ว

บท 16 ใช้ `filter` เลือกการ์ดใบเดียวจากหลายใบ บทนี้ตรงข้าม: locator หนึ่งตัวที่ตรงกับ **หลาย element** (เช่นชื่อสินค้า 10 ชื่อ) แล้วตรวจทั้งกลุ่มพร้อมกัน บท 04 เคยเจอ strict mode violation ซึ่งเกิดเมื่อสั่ง action เช่น `click()` กับ locator ที่ตรงหลายตัว แต่ `expect` บางตัวรองรับหลาย element โดยตรง

## เนื้อหา

### 1. locator ที่ตรงหลาย element

```ts
const names = page.getByRole("list", { name: "รายการสินค้า" }).getByRole("heading");
```

`names` ตรงกับ `<h2>` ทั้ง 10 ใบ ถ้าสั่ง `names.click()` จะเจอ strict mode violation เพราะ Playwright ไม่รู้ว่าจะคลิกอันไหน แต่ assertion สำหรับรายการใช้ได้ปกติ:

### 2. toHaveCount: นับจำนวน

```ts
await expect(names).toHaveCount(10);
```

เป็น web-first assertion (บท 13) จึงรอซ้ำจนจำนวนตรงหรือหมดเวลา หน้า `/products` โหลดรายการจาก API หลังเปิดหน้า ตอนแรกจำนวนเป็น 0 แล้วค่อยเป็น 10 ไม่ต้องรอเอง

`toHaveCount(0)` ใช้ยืนยันว่า "ไม่มีเลย" ได้ แต่ระวังว่าผ่านตั้งแต่ตอนที่รายการยังไม่โหลดเหมือนกัน ควรยืนยันว่าหน้าโหลดเสร็จก่อน (เช่นมีข้อความ "พบสินค้า N รายการ")

### 3. toHaveText แบบ array: ตรวจเนื้อหาและลำดับ

```ts
await page.getByLabel("เรียงตาม").selectOption("ราคาต่ำไปสูง");
await expect(names).toHaveText([
  "สมุดโน้ตลายจุด",
  "แก้วกาแฟเซรามิก",
  // ... ครบทุกใบ
]);
```

ใส่ array เข้าไป Playwright จะเทียบ element ตัวที่ 1 กับข้อความตัวที่ 1, ตัวที่ 2 กับตัวที่ 2 ไปเรื่อยๆ **จำนวนต้องเท่ากันพอดี** และเรียงตามลำดับในหน้า เหมาะกับการตรวจผลการเรียงลำดับมาก และยังรอซ้ำอยู่ จึงไม่ต้องรอให้รายการเรียงใหม่เสร็จก่อน

ข้อความที่ใส่เป็น string จะเทียบแบบ "ข้อความตรงทั้งหมด" (หลังตัดช่องว่างหัวท้าย) ถ้าต้องการแค่ "มีข้อความนี้อยู่" ให้ใช้ `toContainText([...])` ที่รับ array เหมือนกัน

หมายเหตุเรื่องข้อมูล: หนังสือ Playwright กับหมอนอิงลายแมวราคา 450 บาทเท่ากัน แอปคงลำดับเดิมไว้ (หมอนอิงมาก่อน) ลำดับนี้คงที่ใน test ที่เขียนไว้

### 4. first, last, nth: เลือกทีละใบ

```ts
const cards = page.getByRole("list", { name: "รายการสินค้า" }).getByRole("listitem");

cards.first()   // ใบแรก
cards.last()    // ใบสุดท้าย
cards.nth(4)    // ใบที่ 5 (นับจาก 0)
cards.nth(-1)   // ใบสุดท้ายเหมือน last()
```

ตัวที่ได้ยังเป็น locator ตัวเดียว ต่อ `getByRole` หรือใส่ใน `expect` ได้ตามปกติ

ข้อควรระวัง: `nth` ผูกกับ **ลำดับ** ถ้าแอปเปลี่ยนลำดับสินค้า test จะชี้ผิดใบโดยไม่แจ้งเตือน ใช้เมื่อ "ลำดับ" คือสิ่งที่ต้องการตรวจ (เช่นตรวจว่าใบแรกหลังเรียงราคาคือใบไหน) ถ้าอยากได้สินค้าตามชื่อให้ใช้ `filter` ของบท 16

### 5. all(): วนทีละ element

```ts
await expect(cards).toHaveCount(10);
for (const card of await cards.all()) {
  await expect(card.getByRole("img")).toBeVisible();
}
```

`await cards.all()` คืน **array ของ locator** ชี้ไปทีละใบ ตอนที่เรียก วนด้วย `for...of` แล้วตรวจแต่ละใบได้ (ใช้ `forEach` ไม่ได้ เพราะ `await` ข้างในไม่ถูกรอ ดูบท 03)

#### all() ไม่รอ (auto-wait) ให้

นี่คือจุดสำคัญที่สุดของบทนี้ `click()` และ `expect` รอ element ให้เอง แต่ `all()` เป็นแค่ "ถ่ายรูปรายการ ณ ตอนนี้" แล้วคืนทันที ถ้าเรียกตอนที่รายการยังโหลดไม่เสร็จจะได้ array ว่าง `[]` ลูปไม่ทำงานสักรอบ และ test **ผ่านโดยไม่ได้ตรวจอะไรเลย**:

```ts
await page.goto("/products");
// ผิด: รายการอาจยังไม่ขึ้น all() อาจได้ [] แล้วลูปข้ามไปเงียบๆ
for (const card of await cards.all()) {
  await expect(card).toContainText("บาท");
}
```

วิธีป้องกันคือ **รอให้รายการครบก่อนทุกครั้ง** ด้วย `await expect(cards).toHaveCount(10)` (ตามตัวอย่างที่ 2) แล้วค่อยเรียก `all()` และอย่าสลับรายการ (เรียง กรอง ค้นหา) ระหว่างวนลูป เพราะ locator แต่ละตัวใน array ผูกกับ "ลำดับ" (เหมือน `nth(i)`) และหาใหม่ตามลำดับทุกครั้งที่ใช้ ถ้ารายการเรียงใหม่หรือเปลี่ยน มันจะชี้ไปที่ element ใดก็ตามที่อยู่ตำแหน่งนั้นในตอนนั้น ไม่ใช่ใบเดิม

#### เมื่อไหร่ควรใช้ all()

| สถานการณ์ | ใช้อะไร |
|---|---|
| ตรวจจำนวน | `toHaveCount` |
| ตรวจข้อความทั้งรายการและลำดับ | `toHaveText([...])` |
| ตรวจเรื่องเดียวกันกับทุกใบ (เช่นทุกใบต้องมีรูป) | `all()` วนตรวจ (ต้อง `toHaveCount` ก่อน) |
| ต้องทำอะไรทีละใบที่ต่างกัน เช่นกดแต่ละใบ แล้วตรวจผลทีละใบ | `all()` |
| อยากได้ใบเดียว | `first()` / `nth()` / `filter` |

ถ้า `toHaveText([...])` ทำงานได้แล้ว ให้ใช้ตัวนั้นก่อน เพราะรอซ้ำให้ ส่วน `all()` เก็บไว้ใช้เมื่อต้องตรวจเป็นรายใบ

## จุดที่มักพลาด

- **เรียก `all()` โดยไม่รอก่อน**: ได้ `[]` ลูปไม่ทำงาน test ผ่านโดยไม่ได้ตรวจอะไร ให้ `toHaveCount` ก่อนเสมอ
- **ใช้ `forEach` กับ `await` ข้างใน**: ไม่ถูกรอ ใช้ `for...of`
- **`toHaveText` array จำนวนไม่เท่า**: ใส่น้อยกว่าหรือมากกว่าจำนวน element จริงแล้ว fail ให้ดูข้อความ error ที่แสดงทั้ง Expected และ Received เทียบกัน
- **ลืมว่า `toHaveText` เทียบข้อความตรงทั้งหมด**: ชื่อต้องครบ เช่น "หนังสือ TypeScript เบื้องต้น" ไม่ใช่ "หนังสือ TypeScript" ถ้าต้องการแค่บางส่วนใช้ `toContainText`
- **ใช้ `nth` แทน filter**: ใช้ได้แต่จะพังเมื่อลำดับเปลี่ยน (เช่นเปลี่ยนการเรียงเป็นราคา)
- **นับการ์ดด้วย `getByRole("listitem")` ทั้งหน้า**: ถ้าหน้ามี list อื่นด้วยจะนับรวม ต่อจาก `getByRole("list", { name: "..." })` ก่อนเสมอ

## หน้าในแอปที่ใช้

**`/products`**
- `<ul aria-label="รายการสินค้า">` การ์ด 10 ใบ ชื่ออยู่ใน `<h2>` จำนวนต่อหมวด: อุปกรณ์ไอที 3, เสื้อผ้า 2, ของใช้ในบ้าน 2, หนังสือ 3
- ลำดับ "แนะนำ" (ค่าเริ่มต้น): หูฟังไร้สาย DN Buds, เสื้อยืด DN สีขาว, หมอนอิงลายแมว แล้วตามด้วยคีย์บอร์ดเครื่องกล, เมาส์ไร้สาย, หมวกแก๊ป, แก้วกาแฟเซรามิก, หนังสือ TypeScript เบื้องต้น, หนังสือ Playwright ฉบับลงมือทำ, สมุดโน้ตลายจุด
- select "เรียงตาม" (แนะนำ / ราคาต่ำไปสูง / ราคาสูงไปต่ำ) และ "หมวดหมู่" (ทั้งหมด / อุปกรณ์ไอที / เสื้อผ้า / ของใช้ในบ้าน / หนังสือ)
- ช่อง "ค้นหาสินค้า" (กด Enter เพื่อค้นหา)
- ข้อความ "พบสินค้า N รายการ" แสดงเมื่อโหลดเสร็จ

## แบบฝึกหัดในบทนี้

1. กรองหมวด "หนังสือ" (ได้ 3 ใบ) แล้วหมวด "ของใช้ในบ้าน" (ได้ 2 ใบ) ด้วย `toHaveCount`
2. เรียง "ราคาสูงไปต่ำ" แล้วตรวจชื่อสามใบแรกด้วย `first()` และ `nth()`
3. ค้นหา "ไร้สาย" แล้วตรวจชื่อทั้งสองใบด้วย `toHaveText([...])`
4. วนด้วย `all()` ตรวจว่าทุกการ์ดที่ไม่ใช่หมวกแก๊ปมีปุ่ม "เพิ่มลงตะกร้า" ที่กดได้ (อย่าลืม `toHaveCount` ก่อน)
