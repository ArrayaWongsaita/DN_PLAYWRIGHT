# บทที่ 09: เปลี่ยนหน้า ย้อนกลับ และ reload 🏫

## จบบทนี้แล้วทำอะไรได้

- เดินไปมาระหว่างหน้าด้วยการคลิกเมนูและลิงก์ แล้วตรวจ URL ด้วย `toHaveURL`
- ใช้ `goBack`, `goForward` และ `reload`
- ตรวจ URL ได้ทั้งแบบข้อความเต็ม (string) และ regex

## เชื่อมกับที่รู้แล้ว

ที่ผ่านมาเราใช้ `page.goto(...)` พาไปหน้าที่ต้องการทันที บทนี้เป็นการเปลี่ยนหน้าแบบที่ผู้ใช้ทำจริง คือคลิกเมนู คลิกลิงก์ กดปุ่มย้อนกลับ ลิงก์และเมนูหาด้วย `getByRole("link")` ตามบท 04 ส่วนการตรวจว่า "ไปถึงหน้าที่ถูกต้อง" ใช้ `toHaveURL`

## เนื้อหา

### toHaveURL

```ts
await expect(page).toHaveURL("/products");          // string
await expect(page).toHaveURL(/\/products\/p01$/);   // regex
```

- `toHaveURL` ตรวจ URL ของ **page** (ไม่ใช่ locator) และ **รอ** ให้ URL ตรงเหมือน assertion อื่นๆ การเปลี่ยนหน้าไม่ได้เกิดทันที จึงควรใช้ตัวนี้เสมอหลังคลิกลิงก์ แทนการอ่าน `page.url()` ตรงๆ
- แบบ string: ใส่ path สั้นๆ เช่น `"/products"` Playwright จะต่อกับ `baseURL` ใน config ให้เอง (เหมือน `goto`) และต้องตรงทั้งหมด
- แบบ regex: ใช้เมื่อมีส่วนที่ไม่ตายตัว หรืออยากตรวจแค่บางส่วน `$` คือสิ้นสุดข้อความ และเครื่องหมาย `/` ใน regex ต้องใส่ `\` นำหน้า เช่น `/\/products\/p01$/`

### ลิงก์ในเมนูหลักและในการ์ดสินค้า

ลิงก์ชื่อ "สินค้า" มีทั้งในเมนู header และอาจมีที่อื่นของหน้า (เช่นลิงก์ "ดูสินค้าทั้งหมด" ที่หน้าแรก ซึ่งมีคำว่า "สินค้า" อยู่ด้วย) ถ้าเจอหลาย element ให้ระบุว่าลิงก์อยู่ใน landmark ไหน:

```ts
page
  .getByRole("navigation", { name: "เมนูหลัก" })
  .getByRole("link", { name: "สินค้า" })
  .click();
```

`getByRole("navigation", { name: "เมนูหลัก" })` หา `<nav aria-label="เมนูหลัก">` แล้วค่อยหาลิงก์ "ภายใน" ต่อ (locator ต่อกันได้) ส่วนการ์ดสินค้า ชื่อสินค้าเป็นลิงก์ จึงใช้ `getByRole("link", { name: "หูฟังไร้สาย DN Buds" })` ได้เลย

### goBack, goForward, reload

| คำสั่ง | ทำอะไร |
|---|---|
| `page.goBack()` | ย้อนกลับ (เหมือนกดปุ่ม "<" ของ browser) |
| `page.goForward()` | ไปข้างหน้า (หลังย้อนกลับ) |
| `page.reload()` | โหลดหน้าปัจจุบันใหม่ |

```ts
await page.goBack();
await expect(page).toHaveURL("/");
```

ใช้ `await expect(page).toHaveURL(...)` ตามหลังเสมอเพื่อให้แน่ใจว่าอยู่หน้าที่คิด

### reload แล้วข้อมูลยังอยู่ไหม

ตะกร้าของแอปนี้เก็บที่เซิร์ฟเวอร์โดยผูกกับ cookie ของ session ดังนั้นหลัง `reload()` ของในตะกร้ายังอยู่ ข้อมูลที่เก็บแค่ในหน่วยความจำของหน้า (เช่นข้อความที่พิมพ์ค้างในช่อง) จะหายหลัง reload

## จุดที่มักพลาด

- **ตรวจ URL ด้วย `expect(page.url())`**: ไม่รอ ทำให้ผ่านบ้างไม่ผ่านบ้าง ใช้ `await expect(page).toHaveURL(...)`
- **เขียน string URL ผิด**: ต้องตรงทั้งหมด `"/products"` ไม่ตรงกับ `/products?q=หูฟัง` ถ้าสนใจแค่ path ให้ใช้ regex
- **ลืมใส่ `\` หน้า `/` ใน regex**: `/products/p01/` ผิด ต้องเป็น `/\/products\/p01$/`
- **ลิงก์ชื่อสั้นเจอหลายตัว**: เช่น "สินค้า" ใช้ navigation ช่วยระบุ หรือ `{ exact: true }` (บท 04)
- **ใช้ `goto` แทนการคลิก**: `goto` ข้ามขั้นที่ผู้ใช้จริงทำ ถ้าอยากตรวจว่าลิงก์ในเมนูใช้งานได้ ต้องคลิก

## หน้าในแอปที่ใช้

- **`/`**: เมนูหลัก (หน้าแรก, สินค้า, ตะกร้า, เข้าสู่ระบบ), การ์ดสินค้าแนะนำ p01, p04, p07
- **`/products`**: รายการสินค้า ชื่อสินค้าเป็นลิงก์ไป `/products/{id}`
- **`/products/{id}`**: ลิงก์ "← กลับไปหน้าสินค้า"
- **`/cart`**: ตะกร้าสินค้า (h1 "ตะกร้าสินค้า"), รายการ "สินค้าในตะกร้า"
