# บทที่ 45: เทียบภาพหน้าจอ (visual comparison)

บทนี้เขียนให้อ่านเองได้ บทนี้ต่างจากบทอื่นตรงที่ **ตัวอย่างอยู่ใน `test.fixme`** เพราะการเทียบภาพต้องมี "ภาพต้นแบบ" ก่อน และภาพต้นแบบสร้างบนเครื่องของคุณเอง ไม่ได้อยู่ใน repo ตัวอย่างและเฉลยในบทนี้ใช้ chromium (ตัวอย่างไฟล์ภาพเป็นของ macOS) ให้ทำตามขั้นตอนในหัวข้อ "ทำทีละขั้น" ทุกขั้น

## จบบทนี้แล้วทำอะไรได้

- เทียบภาพหน้าเว็บหรือเฉพาะ element กับภาพต้นแบบด้วย `expect(...).toHaveScreenshot()`
- สร้างและอัปเดตภาพต้นแบบด้วย `--update-snapshots`
- ซ่อนส่วนที่เปลี่ยนตลอด (คำทักทาย วันที่ timer) ด้วย option `mask`
- ตั้งความยืดหยุ่นด้วย `maxDiffPixelRatio` และอ่านภาพ expected/actual/diff ใน report เมื่อ test ล้ม

## เชื่อมกับที่รู้แล้ว

Jest มี snapshot test (`toMatchSnapshot`) ที่เก็บผลลัพธ์เป็นข้อความแล้วเทียบ `toHaveScreenshot` คือไอเดียเดียวกันแต่เก็บเป็น "ภาพ" ใช้จับสิ่งที่ assertion ข้อความจับไม่ได้ เช่น สีเพี้ยน ปุ่มซ้อนกัน หรือ layout พัง บท 44 สอนถ่ายภาพเก็บไว้ดู บทนี้ให้ Playwright ถ่ายแล้ว **เทียบให้อัตโนมัติ**

## เนื้อหา

### 1. toHaveScreenshot ทำงานยังไง

```ts
await expect(page).toHaveScreenshot("login.png");
```

- ครั้งแรกที่ยังไม่มีภาพต้นแบบ (baseline) Playwright จะเขียนภาพที่ถ่ายได้เป็นภาพต้นแบบ แต่ถ้ารันโดยไม่ใส่ `--update-snapshots` test รอบนั้นจะถูกนับว่าล้ม (ดูขั้นที่ 2 ในหัวข้อ 5)
- รอบต่อมา Playwright ถ่ายภาพใหม่แล้วเทียบกับภาพต้นแบบทีละพิกเซล ถ้าต่างเกินเกณฑ์ test ล้ม
- ก่อนเทียบ Playwright ปิด CSS animation และรอฟอนต์โหลด แล้วถ่ายซ้ำจนได้ภาพสองภาพติดกันที่ตรงกัน (จึงไม่ต้องรอเอง) แต่ถ้าหน้ายัง "เปลี่ยนสภาพ" อยู่ (เช่น ข้อความยังไม่ขึ้นเพราะหน้ายังไม่พร้อม) ภาพที่นิ่งอาจเป็นภาพของสภาพที่ยังไม่เสร็จ ให้รอ assertion ของสิ่งที่ต้องเห็นก่อนถ่ายเสมอ
- ใช้กับ `page` (ทั้งหน้า) หรือ locator (เฉพาะ element) ก็ได้ และใส่ `fullPage: true` ได้เหมือน `page.screenshot`
- ชื่อไฟล์ภาพใน argument แรกต้องลงท้ายด้วย `.png` และไม่ซ้ำกันในไฟล์เดียวกัน

### 2. ภาพต้นแบบเก็บที่ไหน และทำไมมี `{platform}`

ดู `playwright.config.ts` ของบทนี้:

```ts
snapshotPathTemplate: "{testDir}/{testFileName}-snapshots/{arg}-{projectName}-{platform}{ext}",
```

ตัวอย่างไฟล์ที่ได้บน macOS: `lessons/45-visual-comparison/visual-comparison.spec.ts-snapshots/home-chromium-darwin.png` ส่วนที่แปรผันคือ `{arg}` ชื่อภาพ `{projectName}` ชื่อ project (`chromium`) และ `{platform}` ชื่อระบบปฏิบัติการ (`darwin` = macOS, `linux`, `win32` = Windows)

**ทำไมต้องแยกตามระบบปฏิบัติการ:** แต่ละ OS วาดฟอนต์และขอบตัวอักษรไม่เหมือนกัน แม้ใช้ browser รุ่นเดียวกัน ภาพที่ได้จึงต่างกันเล็กน้อยทุกครั้ง ถ้าใช้ภาพต้นแบบจาก macOS ไปเทียบบน Linux (เช่น บน CI) จะล้มทั้งที่แอปไม่ได้เปลี่ยนอะไร ภาพต้นแบบจึงต้องสร้างแยกต่อ OS (และต่อ browser) ในโปรเจกต์จริงทีมมักสร้างภาพบน CI ที่เป็น OS เดียวกับที่ใช้ตรวจ แล้ว commit ภาพเหล่านั้น ส่วน repo นี้ **ไม่ commit ภาพ** (โฟลเดอร์ `*-snapshots` อยู่ใน `.gitignore`) ทุกคนสร้างภาพต้นแบบของตัวเองก่อนเทียบ ตามขั้นตอนด้านล่าง

### 3. option ใน config: maxDiffPixelRatio

```ts
expect: { toHaveScreenshot: { maxDiffPixelRatio: 0.01 } },
```

- `maxDiffPixelRatio: 0.01` คือยอมให้พิกเซลต่างกันได้ไม่เกิน 1% ของพิกเซลทั้งภาพ (ค่าเริ่มต้นคือไม่ยอมให้ต่างเลย) เหมาะกับขอบตัวอักษรที่ขยับเล็กน้อย
- มี option อื่นที่คล้ายกัน เช่น `maxDiffPixels` (จำนวนพิกเซลแบบตรงๆ) และ `threshold` (ความต่างของสีต่อพิกเซล ระหว่าง 0 ถึง 1) บทนี้ใช้ `maxDiffPixelRatio` ตัวเดียวให้เข้าใจง่าย
- ใส่ option ใน `toHaveScreenshot({ ... })` ตรงๆ ก็ได้ และค่าที่ใส่ใน test **ทับ** ค่าใน config (ข้อ 3 ทำแบบนี้)
- **อย่าตั้งหลวมเกินไป:** ตัวอย่างเช่น การเปลี่ยนสีหัวข้อ h1 เป็นสีแดงอย่างเดียวบนหน้า `/login` ไม่ทำให้ test ล้ม เพราะพิกเซลที่เปลี่ยนน้อยกว่า 1% ของภาพ ความต่างเล็กๆ จะหลุดรอดได้ถ้าเกณฑ์กว้างเกินไป

### 4. mask: ซ่อนส่วนที่เปลี่ยนตลอด

หน้าแรกมี 3 ส่วนที่เปลี่ยนตามเวลาจริง ทำให้ภาพไม่เหมือนเดิมทุกครั้ง:

| ส่วน | locator |
|---|---|
| คำทักทาย | `page.getByTestId("greeting")` |
| วันที่ | `page.getByTestId("today")` |
| timer ของ Flash Sale | `page.getByRole("timer", { name: "เวลาที่เหลือ" })` |

```ts
await expect(page).toHaveScreenshot("home.png", { mask: [greeting, today, timer] });
```

`mask` รับรายการ locator แล้วทาสี่เหลี่ยมสีชมพูทับ element เหล่านั้น **ทั้งตอนสร้างภาพต้นแบบและตอนเทียบ** ภาพทั้งสองจึงเหมือนกันในส่วนนั้น ไม่ว่าเวลาจะเดินไปเท่าไร

**ต้องรอให้ข้อความขึ้นก่อนถ่าย:** คำทักทายและวันที่ถูกสร้างหลังหน้า hydrate เสร็จ (ก่อนหน้านั้นเป็น `<p>` ว่าง สูงไม่เท่าตอนมีข้อความ) ถ้าถ่ายก่อน ความสูงของหน้าจะต่างกันระหว่างรอบ ตัวอย่างจึงมี `await expect(greeting).not.toBeEmpty()` (ข้อความที่ขึ้นแล้วไม่หายไป จึงรอได้อย่างปลอดภัย)

### 5. ทำทีละขั้น (ตัวอย่างในไฟล์)

ทำใน `visual-comparison.spec.ts` และรันด้วยคำสั่งในหัวข้อ "วิธีรันบทนี้"

**ขั้นที่ 1: เปลี่ยน `test.fixme` เป็น `test`** ในตัวอย่าง "หน้าแรกหน้าตาไม่เปลี่ยน"

**ขั้นที่ 2: สร้างภาพต้นแบบ** รันด้วย `--update-snapshots`:

```bash
pnpm test --config lessons/45-visual-comparison/playwright.config.ts --update-snapshots
```

จะเห็นข้อความ `A snapshot doesn't exist at ... writing actual.` (บอกว่ากำลังเขียนภาพต้นแบบ) และ test ผ่าน แล้วมีไฟล์ใหม่ในโฟลเดอร์ `visual-comparison.spec.ts-snapshots/` ลองเปิดไฟล์ `home-chromium-<ระบบของคุณ>.png` ดู จะเห็นกล่องสีชมพูตรงตำแหน่งคำทักทาย วันที่ และ timer

> ถ้าลืมใส่ `--update-snapshots` ในครั้งแรก test จะ **ล้ม** ด้วยข้อความ `A snapshot doesn't exist ... writing actual.` เหมือนกัน แต่ภาพต้นแบบถูกเขียนไว้แล้ว รันซ้ำอีกรอบจึงผ่าน การใส่ `--update-snapshots` ตั้งแต่รอบแรกทำให้ไม่ต้องเห็นสีแดงโดยไม่จำเป็น

**ขั้นที่ 3: รันปกติ (ไม่ใส่ flag)**

```bash
pnpm test --config lessons/45-visual-comparison/playwright.config.ts
```

ต้องผ่าน เพราะภาพเหมือนกับภาพต้นแบบ

**ขั้นที่ 4: ทำให้หน้าตาต่างไป** ใส่บรรทัดนี้ในตัวอย่าง ก่อนบรรทัด `toHaveScreenshot` (เป็นการเปลี่ยนสีพื้นหลังเพื่อเลียนแบบกรณีที่มีคนแก้ CSS):

```ts
await page.addStyleTag({ content: "main { background: yellow; }" });
```

รันปกติอีกครั้ง test จะล้มด้วยข้อความ `expect(page).toHaveScreenshot(expected) failed` และ `... pixels (ratio ...) are different.` (บนหน้านี้ ratio อยู่ราว 0.44 ของคุณอาจต่างเล็กน้อย) ท้ายข้อความ error บอกที่อยู่ไฟล์สามภาพ: `Expected` (ภาพต้นแบบ), `Received` (ภาพที่ถ่ายได้ตอนนี้, ไฟล์ `home-actual.png`) และ `Diff` (ภาพที่ไฮไลต์จุดที่ต่าง, ไฟล์ `home-diff.png`) ไฟล์ actual/diff อยู่ใน `test-results/`

**ขั้นที่ 5: ดูใน report** เปิดรายงาน HTML:

```bash
pnpm report
```

คลิก test ที่ล้ม จะเห็นภาพ expected, actual และ diff ในส่วน attachment ให้เทียบกัน (ภาพทั้งสามเป็นไฟล์ที่ terminal บอกที่อยู่ไว้ด้านบน)

**ขั้นที่ 6: ตัดสินใจว่าจะทำยังไงต่อ** มีสองทางเท่านั้น: ถ้าความเปลี่ยนแปลงนั้น **เป็นความตั้งใจ** (ดีไซน์ใหม่) ให้ลบบรรทัดทดลองหรือคงไว้ แล้วรัน `--update-snapshots` อีกครั้งเพื่อเขียนภาพต้นแบบใหม่ทับ ถ้า **ไม่ได้ตั้งใจ** (บั๊ก) ให้แก้โค้ดของแอปกลับ สำหรับการทดลองนี้ ให้ลบบรรทัด `addStyleTag` ออก แล้วรันปกติ test จะกลับมาผ่าน

## จุดที่มักพลาด

- **ลืมสร้างภาพต้นแบบ** ทำให้ test ล้มรอบแรกด้วย `A snapshot doesn't exist` ใส่ `--update-snapshots` ตอนสร้าง
- **เอา `--update-snapshots` ใส่ทุกครั้งที่รัน**: ภาพถูกเขียนทับตลอด test จึงผ่านเสมอและไม่ได้ตรวจอะไรเลย ใช้เฉพาะตอนตั้งใจเปลี่ยนภาพต้นแบบ
- **ไม่ mask ส่วนที่เปลี่ยนตลอด**: ผ่านรอบนี้ ล้มรอบหน้า (เวลาเดินไปแล้ว) mask ทุกส่วนที่ขึ้นกับเวลา สุ่ม หรือข้อมูลจริง
- **ถ่ายตอนหน้ายังไม่พร้อม**: ภาพต้นแบบเป็นภาพของสภาพที่ยังโหลดไม่เสร็จ ให้รอข้อความหรือ element ที่ต้องเห็นก่อน
- **ใช้ภาพต้นแบบข้าม OS**: macOS กับ Linux วาดฟอนต์ไม่เหมือนกัน ภาพต้นแบบต้องแยกตาม OS (ดูหัวข้อ 2)
- **ตั้ง `maxDiffPixelRatio` กว้างเกินไป**: ความต่างเล็กๆ ที่ควรจับได้จะหลุดรอด (ดูหัวข้อ 3)
- **ตั้งชื่อภาพซ้ำกันในไฟล์เดียวกัน**: ภาพชนกัน ใช้ชื่อที่บอกว่าเป็นภาพอะไร
- **ใช้บ่อยเกินไป**: ภาพต้นแบบต้องดูแลทุกครั้งที่ดีไซน์เปลี่ยน ใช้กับส่วนที่สำคัญและนิ่ง ไม่ต้องถ่ายทุกหน้า

## หน้าในแอปที่ใช้

**`/`** หน้าแรก: `data-testid="greeting"` (คำทักทาย), `data-testid="today"` (วันที่), `role="timer"` ชื่อ "เวลาที่เหลือ" (Flash Sale นับถอยหลัง) และ `<nav aria-label="เมนูหลัก">`
**`/login`** เข้าสู่ระบบ: h1 "เข้าสู่ระบบ" และฟอร์ม ไม่มีส่วนที่เปลี่ยนตามเวลา

## วิธีรันบทนี้

บทนี้มี config ของตัวเอง (ต้องใส่ `--config`):

```bash
pnpm test --config lessons/45-visual-comparison/playwright.config.ts
```

ผลที่ควรได้ก่อนเริ่มทำแบบฝึกหัด: `4 skipped` (ตัวอย่าง 1 ข้อและแบบฝึกหัด 3 ข้อเป็น `test.fixme` ทั้งหมด) เมื่อเปลี่ยนเป็น `test` แล้วต้องสร้างภาพต้นแบบก่อน:

```bash
pnpm test --config lessons/45-visual-comparison/playwright.config.ts --update-snapshots
```

## แบบฝึกหัดในบทนี้

ทำในไฟล์ `visual-comparison.spec.ts` ทุกข้อใช้ขั้นตอนเดียวกับหัวข้อ 5: เปลี่ยนเป็น `test`, สร้างภาพต้นแบบด้วย `--update-snapshots`, รันปกติ

1. เทียบภาพหน้า `/login` (ไม่ต้อง mask)
2. เทียบภาพเฉพาะ nav "เมนูหลัก" (ใช้ `toHaveScreenshot` กับ locator)
3. เทียบภาพหน้าแรกทั้งหน้า (`fullPage: true`) พร้อม mask และตั้ง `maxDiffPixelRatio` ที่เข้มกว่า config

เมื่อทำเสร็จ ลองทำให้ภาพต่าง (เหมือนขั้นที่ 4) กับข้อ 1 หรือ 2 แล้วดู diff ใน report
